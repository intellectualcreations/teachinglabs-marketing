Design Notes

Student Identity Flow

  • Teacher uploads CSV → creates school_roster entries (no account yet, student_profile_id = NULL)
  • Student signs up with class code or QR → matches against roster by name
  • If ambiguous match (multiple students with same name) → last 3 digits of district_student_id used as tiebreaker
  • On match: student_profiles row created, school_roster.student_profile_id linked
  • Roster spelling is canonical. formatName() is input convenience only.

Parent Safety Model

  • Teacher always initiates the connection: generates single-use invite_code (type=parent_invite) per student
  • Parent claims code → parent_student_connections row created with status=active
  • Code is burned on claim (status → claimed). Cannot be reused.
  • Parent dashboard shows "Connected Adults" for each child. Any parent can flag a connection.
  • Teacher can revoke any connection: sets revoked_at + revoked_by, status → revoked
  • If code is compromised: teacher revokes + generates a new one

Class Join Codes vs Parent Invite Codes

  • Class join code (in classes.join_code): reusable, shared with entire class, identifies the CLASS. Used by students + QR codes.
  • Parent invite code (in invite_codes): single-use, per-student, identifies a specific STUDENT. Used only by parents.
  • Both are 6-character alphanumeric. Different namespaces: class codes stored in classes, parent codes in invite_codes.

Auth Strategy

  • SSO (Google, Microsoft, ClassLink): sso_provider + sso_id on users table. No password needed.
  • Email/password: password_hash (bcrypt). Available for all roles.
  • Username/password: Students only. username field. For students without email (home accounts created by parent).
  • Password resets: secure token, 1-hour expiry, single use. Response never reveals if account exists.

FERPA / COPPA Considerations

  • No student PII stored without school/teacher consent (roster upload = consent)
  • Parent connections are teacher-initiated only. No self-service child lookup.
  • Admin access is scoped to their district + selected schools only
  • All connection changes are auditable (timestamps, revoked_by)
  • Student usernames should not contain real names (enforced in UI)
